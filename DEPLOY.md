# Деплой и перенос на другой сервер

Бот работает через polling, поэтому белый IP, домен и SSL не нужны: достаточно доступа сервера к `api.telegram.org`.

## 1. Первый деплой

На сервере должны стоять Docker и плагин Compose (`docker compose version`).

- [ ] `git clone <репозиторий> && cd sample_shop_bot`
- [ ] `cp .env.example .env` и заполнить `TG_TOKEN`, `GROUP_ID`, `POSTGRES_PASSWORD` (без символов `@ : / ? #`)
- [ ] Бот добавлен в группу менеджеров `GROUP_ID`
- [ ] `docker compose up -d --build`
- [ ] `docker compose logs -f bot`: нет ошибок, бот стартовал
- [ ] Проверка: `/start` у бота, `/admin` из аккаунта участника группы, тестовый заказ доходит в группу
- [ ] Бэкапы появляются в `backups/` (первый создаётся сразу при старте сервиса `backup`)

## 2. Бэкапы наружу

Бэкапы лежат на том же сервере, поэтому при поломке диска пропадут вместе с БД. Копировать на другую машину, например раз в сутки с домашнего ПК или сервера:

```bash
rsync -av user@старый_сервер:~/sample_shop_bot/backups/ ~/backups/shop/
```

## 3. Перенос на новый сервер с накопленной БД

Одновременно запускать бота с одним токеном на двух серверах нельзя: будет `TelegramConflictError`. Порядок: остановить старый, поднять новый. Простой около 10–20 минут, лучше делать ночью.

**Подготовка (бот ещё работает на старом сервере)**
- [ ] На новом сервере установлен Docker, склонирован репозиторий (та же версия кода, что на старом: `git log -1` совпадает)
- [ ] Новый сервер видит `api.telegram.org` (`curl -I https://api.telegram.org`)

**Переезд**
1. [ ] Старый сервер: остановить бота, БД не трогать, чтобы новые заказы не писались во время дампа:
   `docker compose stop bot`
2. [ ] Старый сервер: свежий дамп (формат такой же, как у автобэкапа, с `--clean --if-exists`):
   `docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" --clean --if-exists "$POSTGRES_DB"' | gzip > shop_move.sql.gz`
3. [ ] Перенести на новый сервер вместе с `.env`:
   `scp shop_move.sql.gz .env user@новый_сервер:~/sample_shop_bot/`
4. [ ] Новый сервер: поднять только БД:
   `docker compose up -d db`
5. [ ] Новый сервер: восстановить дамп:
   `gunzip -c shop_move.sql.gz | docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" "$POSTGRES_DB"'`
6. [ ] Новый сервер: запустить всё:
   `docker compose up -d --build`
7. [ ] `docker compose logs -f bot`: бот стартовал без ошибок
8. [ ] Проверка: `/start`, каталог на месте, «Мои заказы» показывает старые заказы, тестовый заказ доходит в группу
9. [ ] Старый сервер: убедиться, что бот не запущен, и `docker compose down` (без `-v`, пока не убедишься, что новый работает; том с БД на старом остаётся как запасной вариант)

**Что переносить не нужно**
- Фото товаров: в БД хранятся `file_id` Telegram, они работают с любого сервера при том же токене.
- Группу менеджеров: `GROUP_ID` тот же.
- Незаконченные диалоги (FSM) в памяти: после перезапуска сбросятся, покупателям достаточно нажать `/start`.

## 4. Если что-то пошло не так

- Бот не стартует, в логах конфликт: где-то ещё запущен бот с этим токеном. Остановить его.
- Ошибка при восстановлении дампа: БД на новом сервере должна быть пустой и той же версии PostgreSQL (`16-alpine` зафиксирована в compose). При повторной попытке `--clean` пересоздаст таблицы.
- Откат: на старом сервере `docker compose start bot`, новый остановить.
